# Stance Health — Clinical Assessment Pipeline

WAV clinician session → transcription → LangGraph extraction agent → `FirstAssessment` JSON,
served over FastAPI, persisted to MongoDB.

## Important note on this submission

The dev sandbox this was built in has **no outbound network access to Hugging Face,
`openaipublic.azureedge.net`, or `api.openai.com`** — so Whisper's model weights
can't be downloaded and OpenAI's API can't be reached from inside it. `api.anthropic.com`
is reachable, but no API key was provisioned in that environment either. That means two
of the six pipeline stages (real Whisper transcription, and the LLM extraction call)
could not be executed live *inside that sandbox*, even though the code for both is
real, complete, and will run as soon as it has network access + an API key.

To still deliver a genuine, honest end-to-end run rather than a hand-wavy mock:

- **Transcription**: implemented for real against production Whisper
  (`app/transcription/whisper_service.py`, `faster-whisper`), plus an offline fallback
  (`pocketsphinx`, whose small English acoustic model ships inside its PyPI wheel — no
  download needed). The fallback is real speech recognition, just noticeably less
  accurate than Whisper on clinical vocabulary. `sample_output/` was generated by
  **actually running this fallback on the provided WAV** — see the `transcript` field
  in the output for the raw result, warts and all.
- **Extraction**: the LangGraph agent (`app/agent/graph.py`) and its prompt
  (`app/agent/prompts.py`) are real and will call Claude or GPT-4o given an API key.
  Since no key was available, `scripts/build_demo_output.py` applies the exact same
  hard rules from the prompt by hand to the real transcript, and the result is
  validated through the same `ExtractionEnvelope`/`FirstAssessment` Pydantic models
  the LLM's output would be validated against in production. Every field that was
  genuinely ambiguous in the ASR output (see `extraction_flags` in the output) is
  flagged rather than guessed — per the "never hallucinate clinical values" rule.

Run `LLM_PROVIDER=anthropic ANTHROPIC_API_KEY=... TRANSCRIPTION_ENGINE=whisper python
tests/test_pipeline.py sample_data/clinical_assessment.wav` with real credentials and
network access to see the fully live path.

## Stack

- **FastAPI** — HTTP layer, 4 endpoints
- **faster-whisper** (CTranslate2 Whisper) — transcription, CPU int8 by default
- **pocketsphinx** — offline transcription fallback (no network dependency)
- **LangGraph** — `transcribe → extract → validate → finalize` state machine, with a
  bounded retry loop back to `extract` if the LLM's JSON fails schema validation
- **Pydantic v2** — the `FirstAssessment` schema is the single source of truth; the
  LLM's raw output is validated against it before anything is returned or persisted
- **Motor** (async MongoDB driver) — storage

## Design decisions

**Why a separate `ExtractionEnvelope` instead of stuffing confidence/flags into
`FirstAssessment` itself?** The brief is explicit that the schema must exactly match
what the frontend consumes — no extra fields. Confidence and flag metadata are real
and useful (for a review UI, for the 422 threshold check) but they are *not* part of
the frontend's contract, so they live in a wrapper the API layer uses, not in the
schema the frontend parses. `GET /assessments/{id}` currently returns the full stored
document (assessment + metadata) since a review/audit UI benefits from seeing
confidence and flags; swap to returning only `doc["assessment"]` if the frontend needs
the bare schema with nothing else.

**Why never emit `null` for string fields?** Pydantic validators (`_none_to_empty_str`)
coerce any `None` the LLM might emit into `""` before validation, since the brief
requires strings to always be strings. Arrays default to `[]` via `Field(default_factory=list)`
for the same reason — a single extracted item is still wrapped in a list.

**No-hallucination enforcement is layered, not just prompted:**
1. The system prompt states the rule explicitly and gives a concrete strategy for
   ambiguous values (put raw text in `comments`, leave `left`/`right` empty, flag it)
   rather than just saying "don't hallucinate."
2. `validate_node` re-prompts the LLM (bounded to 2 retries) if its JSON doesn't parse
   or doesn't satisfy the schema — it does not silently coerce malformed output.
3. If extraction still doesn't validate after retries, `finalize_with_failure_node`
   returns an **empty, schema-valid** envelope with `overall_confidence: 0.0` rather
   than ever returning fabricated content.
4. `POST /assessments/parse` returns **HTTP 422** with the flagged fields and raw
   assessment attached when `overall_confidence` is below `EXTRACTION_CONFIDENCE_THRESHOLD`
   (default `0.4`), so a low-quality automatic parse never silently reaches the
   frontend as if it were reliable.
5. When the transcription engine itself is the low-accuracy offline fallback (not
   Whisper), `validate_node` clamps `overall_confidence` to at most 0.5 regardless of
   what the LLM reports, since a clean-looking JSON extracted from a garbled
   transcript is still only as trustworthy as the transcript.

## Setup

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in ANTHROPIC_API_KEY or OPENAI_API_KEY, Mongo URI
```

Start MongoDB (or point `MONGO_URI` at an existing instance), then:

```bash
uvicorn app.main:app --reload
```

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/assessments/parse` | multipart WAV upload → transcribe → extract → `FirstAssessment` JSON (+ confidence/flags). Returns 422 if confidence is below threshold. |
| POST | `/assessments` | persist a parsed result (e.g. the output of `/parse`) to MongoDB |
| GET | `/assessments/{id}` | retrieve one saved assessment by id |
| GET | `/assessments?start_date=&end_date=&limit=&skip=` | list saved assessments, filterable by date range |

## Running the tests

```bash
pytest tests/ -v
```

`test_pipeline.py`'s `test_schema_roundtrip` and all of `test_api_endpoints.py` need no
network access or credentials. Running `python tests/test_pipeline.py sample_data/clinical_assessment.wav`
as a script (not via pytest) exercises the real pipeline end-to-end and needs
`TRANSCRIPTION_ENGINE`/`LLM_PROVIDER` credentials for the live-Whisper / live-LLM path,
or `TRANSCRIPTION_ENGINE=pocketsphinx` to run everything except live-Whisper offline.

## Known limitations / what I'd do next with more time

- The offline ASR fallback (pocketsphinx) has a materially higher word-error-rate on
  clinical/anatomical vocabulary than Whisper — several numeric values in the demo
  transcript (hip rotation figures) came through too garbled to safely structure, and
  are flagged rather than guessed. This is a transcription-quality problem, not an
  extraction-agent problem; solved entirely by running with `TRANSCRIPTION_ENGINE=whisper`
  and network access.
- No auth/rate-limiting on the endpoints — out of scope for the brief but would be
  needed before any real deployment.
- `EXTRACTION_CONFIDENCE_THRESHOLD` is a single scalar; a production version would
  likely want per-section thresholds (e.g. tolerate a missing `patientAdvice` more than
  a missing `objectiveAssessment.tests`).
